# 手写字迹 → 透明矢量 SVG

## 环境

技能目录是 `~/.claude/skills/handwriting-svg`，所有依赖都装在这个目录的 `.venv` 里。potrace 由 Homebrew 安装。

```bash
HW=~/.claude/skills/handwriting-svg
PY=$HW/.venv/bin/python
```

如果 `$PY` 不存在或导入报错，先运行 `bash $HW/setup.sh`。这个脚本可以重复执行，会安装 potrace、创建 venv 并装好固定版本的依赖。

加 `--with-waifu2x`（即 `bash $HW/setup.sh --with-waifu2x`）会顺带安装 waifu2x-ncnn-vulkan，用于轮廓放大，能明显减少断笔。它是 GitHub 官方发布的 20250915 版，MIT 许可，约 40MB，下载后会做 SHA-256 校验。

## 输入质量（先告诉用户）

**优先用手机的“扫描文稿”（iOS 备忘录/文件 App 的扫描、Adobe Scan、Microsoft Lens 等）导出的 PDF 或图片，而不是直接拍照。**

实测同一页笔记的对比：

| | 扫描 PDF | 直接拍照 |
|---|---|---|
| 汉字高度 | 约 66 像素 | 约 33 像素 |
| OCR 准确率 | 100% | 96% |
| 透视和背景 | 已矫正、已裁剪 | 有透视，带桌面、线圈等杂物 |

直接拍照时细笔画会被光学模糊晕粗，矢量化后字显得肥、糊。这是源图分辨率不够造成的，算法补不回来。

如果只能拍照：
- 让纸张尽量占满画面，正对纸面拍，光线均匀；
- 不要用美颜或“文档增强”这类强锐化滤镜。

扫描时，滤镜选“灰度”或“彩色”，不要选“黑白”。黑白滤镜会把印刷横线和墨迹都压成纯黑，丢掉笔画边缘的灰度过渡：横线只能靠粗细区分，贴着横线写的细笔画（比如“一”）可能缺一截，边缘也更毛。

## 基本用法

```bash
# 推荐: 带 OCR(切分更准, 文件名带识别出的字, 中文逐字/英文逐字母自动处理)
$PY $HW/scripts/hw2svg.py 扫描的文稿.pdf -o out/ --ocr
$PY $HW/scripts/hw2svg.py photo.jpg -o out/ --ocr

# 不用 OCR 切字(纯几何, 更快): 中文逐字; 纯英文请加 --script latin
$PY $HW/scripts/hw2svg.py photo.jpg -o out/
# 英文按单词而不是逐字母
$PY $HW/scripts/hw2svg.py notes.jpg -o out/ --ocr --unit word

# 批量: 多个文件、目录、多页 PDF 都行, 每页输出到 out/<名称>/
$PY $HW/scripts/hw2svg.py scans/ -o out/ --ocr
```

支持的输入格式：
- 图片：jpg、png、bmp、tif、webp。HEIC 会自动用 macOS 的 `sips` 转换。
- PDF：优先无损抽取内嵌的扫描图像；没有内嵌图像时，用 Ghostscript 以 300dpi 渲染。

不加 `--ocr` 时，默认仍会用 OCR 的文字检测框圈定书写区域（`--roi auto`），以去掉线圈、桌面、鼠标、纸边等杂物，只是切字不用 OCR。

## 输出结构

```
out/
  page.svg          整页(默认裁到笔迹范围), 每行是一个 <g id="L01"> 分组
  lines/L01.svg     逐行
  chars/L01_C001_今.svg   逐字(开 --ocr 时文件名带识别文字; OCR 漏识的字只有编号)
  manifest.json     每行/每字的 bbox(page.svg 坐标系)、识别文字、置信度; page.origin 为 page.svg 在纠偏后原图中的位置
  page_clean.png    透明底 PNG(带抗锯齿)
  preview.jpg       检查用: 原图上叠加书写区域(蓝)、行框(绿)、字框(红)
```

- 所有 SVG 都是透明背景，只有填充路径，坐标单位是原图像素，可以无损缩放。按 manifest 里的 `bbox` 把各个 SVG 放回原位，就能精确还原整页。
- 轮廓画在每个笔画最深处与纸色的正中间，还原的是真实粗细，而不是二值化阈值处那圈偏粗的灰晕。觉得太细或太粗，可以用 `--edge` 调。
- 单字画布默认 `--char-canvas line`：高度等于整行高度，宽度贴字，同一行的字横排拼接时基线自然对齐。另有 `tight`（紧贴笔迹）和 `square`（正方形，适合做字库）两种模式。

## 拼接

```bash
# 按文字挑字重排(需要 --ocr 生成的 manifest), \n 换行, 缺的字留空并提示
$PY $HW/scripts/stitch.py --manifest out/manifest.json --text "天气很好\n明月几时有" -o new.svg
# 按文件顺序拼一行, 每 10 个换行, 字距 4px, 改成蓝色
$PY $HW/scripts/stitch.py out/chars/L01_*.svg --wrap 10 --gap 4 --color "#1f3a93" -o row.svg
# 把几行纵向拼成一页
$PY $HW/scripts/stitch.py out/lines/L01.svg out/lines/L03.svg --vertical -o page2.svg
```

按文字挑字时，所有字按同一比例缩放（默认保持原始大小，可用 `--height` 指定典型字高），并按各自所在行的基线对齐，保留书写时字与字之间真实的大小关系。按文件拼接时，则统一到画布高度的中位数，加 `--no-scale` 可保持原尺寸。同一个字有多个手写样本时，`--pick cycle`（默认）会轮流使用，看起来更自然。

## 工作流程（给 Claude）

1. 跑完后一定先看 `preview.jpg`，检查三件事：蓝框是否框住了全部手写内容，绿框分行是否正确，红框分字是否正确。再看 `page_clean.png`，确认横线去干净了、笔画没缺。
   - 要看矢量结果本身，用 `$PY $HW/scripts/svg2png.py in.svg out.png --scale 2` 渲染。这个工具和浏览器渲染一致；不要用 OpenCV 的抗锯齿填充自己画，它每条边会多涂约半个像素，字会显得发粗。
   - 给用户看对比图时，原图和 SVG 要用同一比例。原图只做同样的纠偏旋转；page.svg 按 manifest 的 `page.origin` 放回原图坐标。
2. 发现问题时按下表调整，然后重跑：

| 现象 | 调整 |
|---|---|
| 笔画偏粗或偏细 | 实测默认值下，SVG 与原图笔画（按半灰度量）的面积差在 2% 以内。纯黑填充、边缘锐利，看上去会比原图偏灰、带柔边的墨迹略重；可以用 `--color auto` 取原墨水颜色，或用 `--edge 0.4` 稍微收细（默认 0.5，调大变粗） |
| 太慢或内存不够（大幅扫描件放大后像素多） | `--upscale off`，或 `--upscale bicubic`（不调用 waifu2x）。manifest 的 `upscale` 记录了实际用的方式 |
| 去模糊后出现噪点、振铃（笔画边上有浅色“回声”） | `--deblur off` 关闭，或给更小的 σ，比如 `--deblur 0.4`；manifest 的 `deblur_sigma` 记录了自动估计值 |
| 边缘有毛刺，或拐角太圆 | `--smooth`（默认 1.0）：调到 1.3 更平滑，调到 0.6 保留更多细节；`--alphamax 0.8` 保留更多拐角 |
| 有手写内容在蓝框外被丢了 | `--roi off`，或手动指定 `--roi x0,y0,x1,y1`（纠偏后原图坐标，可从 manifest 的 page.origin 换算） |
| 线圈、桌面等杂物进了结果 | 手动指定 `--roi`；或把图先裁好 |
| 字迹太淡、细笔画断开 | 白纸上可加 `--hysteresis 0.5`（滞后阈值：与深色笔画相连的淡墨也保留，孤立淡斑不收）；也可以 `--threshold 215`（调高更敏感，默认自动 Otsu）。横线纸上慎用滞后阈值，实测会干扰去线 |
| 横线没去干净 | `--rule-cover 0.15`（降低整线覆盖率要求） |
| 压在线上的横笔画（如“一”）缺了 | 多出现在印刷线和墨迹一样黑、一样粗时（扫描用了黑白滤镜）；改用灰度扫描，或加 `--keep-rules` 保留横线 |
| 手画的长横线、下划线、波浪线被删掉 | 默认会保留不在等距网格上、或明显更黑、更粗、不直的线；如果正好画在印刷线上，只能加 `--keep-rules` |
| 线圈、装订孔被当成文字 | 默认只采信“置信度 ≥ 0.85 且至少 2 个字”的 OCR 行来圈定书写区域；仍有残留就手动指定 `--roi` |
| 分字不准 | 加 `--ocr`；英文想按词切用 `--unit word` |
| 行分错（字跨格书写） | `--lines profile` |
| 想保留原墨水颜色 | `--color auto`，或 `--color "#203060"` |

3. `--debug` 会把中间结果写到 `debug/` 目录：光照拉平后的图、二值图、去线去噪后的图，方便定位是哪一步出了问题。

## 处理原理（排查时参考）

1. **读入与预处理**：PDF 先抽出内嵌图像。先去模糊：从粗笔画半高处的边缘斜率估计成像模糊的 σ（3×3 差分下，斜率/对比度 = erf(1/(σ√2))/2，反解得到 σ），再做 10 轮 Richardson–Lucy 去模糊，结果记在 manifest 的 `deblur_sigma`。合成评测上，照片级 F1 从 0.73 提到 0.76、粗细比从 1.20 降到 1.12；扫描级断笔从 42 处降到 29 处，噪点不增加。对已经很锐利的扫描件（σ < 0.3）自动跳过。光照拉平是在缩小的图上做最大值滤波加中值滤波，估计纸面亮度，再用原图除以它，去掉阴影和渐变。之后做 Otsu 二值化。纠偏先用 Hough 找长直线，找不到再用文字行投影，最后做 ±0.5° 的细搜索。
2. **去横线和竖线**：用更靠近纸色的阈值单独检测横线位置，因为淡横线在二值图里常常只剩残段。
   - 检测按约 700 像素宽的竖条分别进行，以适应纸面弯曲、透视造成的各处倾角不同；检测时先竖向膨胀，容忍 1 像素的台阶。
   - 印刷线与手画线的区分：印刷线等距排列，与上下邻线相距约一个线距。不符合这一点的，或者明显更黑（线芯灰度取直方图众数）、更粗（竖向黑段取低分位）、不直（只看细像素做直线拟合）的线，判为手画，予以保留。
   - 删除印刷线后补回笔画，有三个依据。几何：线的上下都有墨迹，做竖向闭运算桥接。粗细：竖向黑段明显比印刷线厚，说明笔画压在线上。光度：比这条线自身最暗处还黑。
3. **去杂物**：
   - 书写区域取可信 OCR 行框的外接矩形，左右留一倍、上下留 0.6 倍行高；连通域重心在区域外的整块丢弃。“可信”指置信度 ≥ 0.85 且至少 2 个字，不贴图像边缘，也不明显矮于正文。线圈常被高置信度地读成“N”“in”这类一两个字符，靠这几条排除。
   - 线圈、阴影等粗黑块删除，判据是最大内切圆直径超过典型笔画粗细的 2.5 倍。
   - 孤立的小噪点删除；但紧挨大笔画的小点（“文”“字”“讠”的点）保留。
4. **分行**：有横线时按横线分格，漏检的淡线按等距补齐；没有横线时用水平投影。之后有三步修正：
   - 垂到下一格的标点和笔画，归回“行芯”最近的那一行；
   - 竖直范围重叠过半的两行合并（字骑在横线上书写的情况）；
   - 远离正文的零星笔迹（勾号、批注）自成一行。
5. **分字**：
   - 开 `--ocr` 时：把笔画列（按水平空隙划分）用动态规划按顺序对齐分配给 OCR 字框，切点只落在真实空隙里，粘连处在投影最细处切开。
   - 不开 OCR 时：用动态规划把偏旁组合成宽度最接近字号的方块字，贴着行底的小块单独算作标点。
6. **轮廓放大**（`--upscale auto`，行高 < 120 像素时启用）：结构步骤（去线、分行、分字）都在原分辨率完成，只有轮廓在放大 2 倍的图上计算，SVG 坐标仍按原图像素。
   - 放大用 waifu2x（`tools/` 下的 waifu2x-ncnn-vulkan，upconv_7_photo 模型、去噪 1 级，在 Apple GPU 上运行）；没装就用双三次插值。
   - 合成评测结果，照片级：F1 从 0.76 提到 0.83，断笔从 203 处降到 102 处，粗细比 1.04；扫描级：F1 从 0.94 提到 0.96，断笔从 29 处降到 23 处。
   - 只用双三次放大时：照片级 F1 0.84，断笔 133 处。
   - 曾试过全流程都在 2 倍图上跑：去线等步骤里有很多和分辨率相关的常数，会出新问题，所以只放大轮廓这一步。
7. **矢量化**：逐像素取“附近 1.5 个笔画宽范围内的最深处”，轮廓定在它与纸色正中间的等值线上（局部半高，Bernsen 式）。放大 3 倍并轻度高斯平滑后，交给 Potrace 生成贝塞尔曲线。
   - 笔压深浅不一时，深处和浅处都按各自的深浅定边界：浅处不断，深处不肥。
   - 也不会被单个噪点像素带偏。照片噪点大，如果取整个笔画的最暗像素当墨芯，半高线会压得太深，细笔画就碎了。
   - 合成评测集（已知字形加上模糊、噪点、JPEG、笔压变化、横线）上的结果：扫描级分辨率 F1 从 0.85 提到 0.93，断笔从 109 处降到 40 处，粗细比约 1.0；照片级（字高约 32 像素）F1 从 0.70 提到 0.73，粗细比约 1.15。
   - 照片级偏粗是物理限制：笔画比镜头模糊的光斑还细时，半高宽主要反映光斑。把 `--edge` 调小会急剧增加断笔，所以不建议调。

## 局限

- 只支持横排。竖排的古籍或书法需要先把图片旋转 90°。
- 拍照时的透视不做矫正，只做整体纠偏。透视明显时请用扫描 App。
- 田字格、米字格里的虚线和斜线去不掉。
- 印刷线和墨迹颜色深浅几乎一样时，压在线上的横笔画可能缺一小段。
- 不开 OCR 时，中英混排的行会按中文规则切分。
- 潦草字的 OCR 文字可能识别错，只影响文件名和 manifest 里的 text，不影响 SVG。
